# Протокол оценки прототипа

## Задача

Проверить, помогает ли память подтверждённых действий формировать более корректные ответы на новые корпоративные задачи, чем исходная история или её резюме. Сравнение проводится с одной моделью исполнителя и одинаковыми контрольными задачами.

## Данные и методы

В локальную базу импортированы 354 задачи из выгрузки. Для расширенного сравнения отобраны десять контрольных задач одной области; у каждой есть три похожие истории, завершённые до её создания. Сведения о задачах, подготовленные контексты и ответы хранятся в исключённой из Git папке `data/`. Автоматическая очистка прямых идентификаторов не гарантирует полного обезличивания; подготовленный текст следует проверить перед сетевым вызовом.

Сравниваются исходный текст найденных задач, резюме того же текста и действия из проверенной памяти. Новая версия допускает в рекомендации лишь записи с исходом `succeeded` и отдельно подтверждённым типом `solution`. События сопровождения и записи с неясным типом исключаются. Нельзя считать статус «Завершена» подтверждением успеха отдельного действия. Подтверждение в памяти действительно только пока исходная задача не изменилась.

## Что измерять

Для каждого черновика следует оценивать корректность по шкале 0–2, применимость к контрольной задаче, наличие неподтверждённых утверждений и точность ссылок. Отдельно учитывать отказ от ответа, время и число вызовов модели. До вскрытия ключа методов оценки должны быть слепыми. Для окончательного вывода нужны несколько независимых специалистов и согласование их оценок. Для сравнения поиска с экспертными метками можно использовать `evaluate --cases data/cases.json --k 5`; он считает долю попаданий, неподходящих источников и отказов.

## Полученные результаты

Первый запуск на десяти задачах выявил ошибку представления опыта: среди записей с меткой успешного действия были назначения исполнителя, переносы сроков и другие события сопровождения. Его результаты сохранены только локально и не подменяются результатами новой версии.

После введения отдельного типа действия 15 очевидных организационных событий получили предварительную метку `administrative`, три неоднозначные записи остались `unknown`. Модель предложила 49 черновых действий по восьми другим историям. Автор сверила с комментариями и подтвердила три содержательных действия; остальные черновики автоматически в память не допускались.

На новом наборе из десяти задач YandexGPT подготовил десять ответов по исходным текстам, десять по резюме и один ответ по проверяемой памяти. В девяти случаях память воздержалась из-за отсутствия подходящего подтверждённого опыта. Таким образом, всего получено 30 вариантов, включая девять отказов.

Баллы 30 вариантов сначала были предложены ИИ-ассистентом по формальной шкале 0–2, затем все проверены и подтверждены автором. Средние баллы по десяти задачам составили 0,90 для исходных текстов, 0,80 для резюме и 0,10 для проверяемой памяти. Неподтверждённые утверждения отмечены соответственно в 1, 3 и 0 вариантах. Вложения к задачам не изучались. Эта авторская разметка не является независимой оценкой специалиста; девять нулей памяти отражают прежде всего её низкое покрытие.

Новый набор использовался для диагностики покрытия после доработки памяти, поэтому его нельзя выдавать за полностью скрытую независимую проверку. Для дальнейшего сравнения нужны больше проверенных решений и новая выборка, не просмотренная при настройке метода. Все исходные задачи, ответы, ключ слепой оценки и разметка хранятся только в локальной папке `data/` и не публикуются вместе с кодом.
